Tarefa: gere fluxo para o ticket informado.
Forme um fluxo sem ciclos. Cada destino deve existir e cada ramo termina em uma ação.
Retorne apenas um objeto JSON com inicio, nos e ascii_diagram; cada nó tem id e decisão com destinos ou acao_terminal.
Exemplo de estrutura:
{
  "inicio": "verificar",
  "nos": [
    {
      "id": "verificar",
      "condicao": "A falha se repete?",
      "destinos": {
        "sim": "coletar",
        "nao": "acompanhar"
      }
    },
    {
      "id": "coletar",
      "acao_terminal": "Registre a etapa e a mensagem."
    },
    {
      "id": "acompanhar",
      "acao_terminal": "Informe quando a falha voltar."
    }
  ],
  "ascii_diagram": "[Verificar] -> Sim: coletar | Não: acompanhar"
}

Instrução adicional de v2: Use condições verificáveis e explicite o resultado de cada ramo.

Comece com uma verificação observável e ofereça ramos para sinais diferentes. Cada caminho termina
em ação, solução confirmada ou encaminhamento com dados concretos. Se o relato já informa uma
verificação, siga adiante. Preserve os IDs e os formatos; o diagrama deve representar os mesmos ramos.
